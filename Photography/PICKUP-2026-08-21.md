## ⚠️ Verification: the in-app browser pane CANNOT test this page

The Browser pane reports `document.hidden = true`, never fires
IntersectionObserver, and starves `requestAnimationFrame` — the canvas stays
blank and it looks like a bug that is not there. **Verify with Playwright
(system `python3`, already installed).** The reusable shooter from this session
is in the scratchpad as `shoot2.py`; the pattern is:

- launch chromium, context at 1440×900 (or 390×844 `is_mobile` `device_scale_factor=2`, or `reduced_motion="reduce"`)
- `goto`, then `wait_for_timeout(4500)` so the assembly finishes
- scroll to a runway fraction with `window.scrollTo({top: …, behavior: 'instant'})` — `behavior:'instant'` is mandatory because `html { scroll-behavior: smooth }` would animate it
- screenshot, read `document.querySelector('[data-instrument-log]').textContent` to know which phase you are in
- assemble a contact sheet with Pillow so many scroll positions can be read at once

Also: the starfield twinkles, so md5 screenshot comparison always reports a
difference. Use a thresholded pixel diff (or hide `.stars`) when asserting that
something did NOT change.

## Traps already paid for (do not rediscover)

- ⭐⭐ **A CSS `animation` on `opacity` overrides inline `style.opacity`.** The
  chrome entrances had to move out of CSS and into the script, or the cue never
  faded out.
- ⭐⭐ **Do not gate rendering on `document.hidden`.** Browsers already stop rAF in
  hidden tabs, and embedded viewers lie about visibility. Gate on
  IntersectionObserver only.
- Lathe profiles must be traced counter-clockwise in the (r, z) half-plane or the
  revolved faces point inward. Glass groups stay double-sided.
- The reduced-motion block un-pins the stage, so the stage box then includes the
  photograph. `measure()` therefore reads the **canvas** rect, never the stage's.
